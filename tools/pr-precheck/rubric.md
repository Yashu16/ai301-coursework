# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | Every changed file and hunk in the diff, read against the plan's files, in-scope list, out-of-scope list, and any deviation notes. | Pass if every changed file and hunk is inside the plan's stated scope or recorded in a deviation note, AND every change the plan promised is present in the diff or its absence is disclosed in a deviation note or in the description. Fail if the diff does something the plan did not ask for (a new option, flag, rename, rewrite, or unrelated file) with no note, or silently omits something the plan promised. An honestly disclosed deferral or deviation passes. | required |
| description-matches-diff | Each claim in the description and title (what changed, "exactly as planned", "no other changes", "docs updated", "tests added"), read against the diff and commits. | Pass if every claim is true of the diff: nothing is claimed that the diff does not contain, and no change in the diff contradicts a claim of fidelity or "no other changes". Fail if the description claims more than the diff delivers (a docs update or test that is not in the diff) or claims fidelity the diff contradicts. | required |
| test-evidence-is-decisive | The test evidence, read against the plan's test plan and the repro's trigger and expected-after. | Pass if the evidence re-runs the reproduced trigger (the plan's own steps, not only a control or a nearby path) on the branch and shows an observable before and after, such as output, exit code, or a failing-then-passing test, matching what the plan said it would show. Fail if the evidence is only "tested locally", "tests pass", "works for me", exercises only the unchanged path or a control, or skips a failure mode the plan's test plan named. | required |
| repo-checks-run | The test evidence read against the checks the repo's PR template or contributing docs list (tests, lint, typecheck, and similar). | Pass if each listed check's actual outcome is visible in the evidence, and a failing or unavailable check is reported honestly with its reason. Fail if a listed check is never shown, or a Testing box is ticked with no evidence behind it. | required |
| diff-is-reviewable | The diff and commit list, read for debris: debug prints, commented-out code, dead or unused functions, stray TODOs, formatting or import churn, and hunks unrelated to the change. | Pass if the diff contains only the change and its tests, with no debug leftovers, commented-out code, dead code, or churn hunks. Fail if any of these is present, even when the core fix is right. Commit messages like "wip" or "misc cleanups" are supporting evidence, never the deciding fact. | required |
| template-and-policy-met | The description, read against the repo-facts block (live: `.github/PULL_REQUEST_TEMPLATE.md`, `docs/CONTRIBUTING.md`): the template's required sections and asks, the issue-link line, any required changelog or whatsnew entry, and the repo's AI-use disclosure policy. | Pass if every section and ask the repo states is filled with real content or honestly marked N/A with a reason, any required file change the repo names is in the diff, and an AI-use disclosure is present in the description in the author's own words wherever the repo states an AI policy (this course treats all work as AI-assisted; in live mode the template's Notes for Reviewers carries it). Fail if a required section or ask is blank or boilerplate, a required entry is missing from the diff, or the disclosure is absent where a policy or template asks for it. | required |
| maintainer-direction-engaged | The issue thread highlights (live: the issue thread), read against the description and diff. | Pass if explicit maintainer direction in the thread (a requested approach, a named constraint, an existing PR) is engaged by the PR, or the thread has none. Fail if the PR ignores or contradicts direction the maintainer gave. | preferred |
| title-is-specific | The PR title read against the change. | Pass if the title names the actual change so a reviewer could tell from the title alone. | preferred |

## Verdict rule

Accept if every `required` check passes. Reject if any `required` check fails. `unclear` on a required check counts as fail: a PR whose evidence cannot be found in the package is not ready to submit. `preferred` checks never change the verdict; report them in the summary only. An honestly disclosed shortfall is not a failure: if the plan's deferral, a deviation, or an unavailable check is stated in the plan or description and the diff matches that statement, the relevant check passes. Only the undisclosed gap fails.
